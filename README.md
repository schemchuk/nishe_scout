
# Niche Scout v2

## Призначення

Знайти і запустити мікро-SaaS у чужому маркетплейсі, де основним каналом залучення може бути внутрішній пошук/дискавері маркетплейсу, без outbound-продажів.

Проект оптимізований під solo-розробника з майже нульовим стартовим капіталом.

## Філософія

Ми не шукаємо просто «прибуткову нішу».

Ми шукаємо ланцюжок:

`marketplace → search intent → pain → switching wedge → install → activation → payment`

Код починається тільки після `DECISION.md = BUILD`.

## Файли

- `CONTEXT.md` — канонічні правила проекту.
- `AGENTS.md` — правила для Kimi / Claude Code / інших AI-агентів.
- `RESEARCH.md` — єдиний робочий журнал дослідження.
- `DECISION.md` — єдиний документ із фінальним рішенням `BUILD` або `REJECT`.

## Рекомендований порядок

### Етап 1 — desk-check маркетплейсів

Перевірити Wix, Shopify, Atlassian і WordPress за мінімальним набором фактів.

Не досліджувати категорії глибоко.

### Етап 2 — відсіяти маркетплейси

Маркетплейс відкидається, якщо немає публічних доказів органічного шляху нового платного app до discovery/install.

### Етап 3 — keyword-level research

На одному маркетплейсі перевірити конкретні пошукові запити, а не абстрактні категорії.

### Етап 4 — pain + switching

Шукати повторювану проблему та докази, що користувачі готові змінити наявне рішення.

### Етап 5 — wedge

Сформулювати одну вузьку причину, через яку новий app має сенс встановити замість лідера.

### Етап 6 — decision gate

Заповнити `DECISION.md`.

- `BUILD` → починається технічне проектування.
- `REJECT` → кандидат закривається, без написання MVP.

## Заборонено обходити процес

Не переходити до коду через аргументи типу:

- «ідея виглядає класно»;
- «конкурент поганий»;
- «ринок великий»;
- «зробимо дешевше»;
- «потім розберемося з distribution».

Це проект із доказами, а не з інтуїцією.
